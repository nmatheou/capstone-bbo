# Capstone Black-Box Optimization (BBO)

This repository contains the codebase and weekly submissions for a Black-Box Optimization capstone project. The objective is to find the global maxima of 8 unknown, continuous black-box functions with varying dimensionalities (ranging from 2D to 8D) over a multi-week period.

## Methodology

The core optimization strategy relies on **Bayesian Optimization** using Gaussian Processes (GPs) as the surrogate model. 

### Surrogate Modeling
- **Model:** Gaussian Process Regressor (`scikit-learn`).
- **Kernel:** Matérn kernel with $\nu = 2.5$, allowing for flexible modeling of both smooth and rugged landscapes. We initialize length scales dynamically based on the dataset variance.
- **Normalization:** The `StandardScaler` is used on the targets ($y$) to ensure stable GP fitting, especially for functions with extreme scales (e.g., F5 reaching into the thousands).

### Acquisition Strategy
The project employs a dynamic acquisition strategy that adapts as we learn more about the function landscapes:
- **Upper Confidence Bound (UCB):** Used primarily in the early weeks and for high-dimensional functions (F6, F7, F8) to balance exploration and exploitation. The $\kappa$ parameter is tuned to encourage searching highly uncertain regions.
- **Expected Improvement (EI):** Switched on in later weeks for stable functions where a clear peak has been identified (e.g., F4, F5). This forces the optimizer to exploit the known "hot" regions to inch closer to the true summit.

### Diagnostics & Tooling
To aid decision-making, we developed several custom diagnostic tools:
- `length_scale_tracker.py`: Tracks the GP length scales across weeks to calculate the Coefficient of Variation (CV). This helps us classify functions as **STABLE** (trust the model, switch to EI) or **VOLATILE** (keep exploring).
- **Oracle Sensitivity Testing:** By monitoring which length scales hit the upper bound limit (e.g., 50.0), we can definitively identify and ignore "irrelevant" dimensions (e.g., F7's $d_3$ and F8's $d_8$) that have no impact on the oracle score.
- **Manual Overrides:** For tricky, multi-modal, low-dimensional functions (like F1 and F3), we augment the algorithmic suggestions with manual overrides based on 3D surface plot visual inspections and opponent triangulation.

## Repository Structure

- `bbo_optimize.py`: The core optimization engine that reads historical data, fits the GPs, maximizes the acquisition functions, and outputs the next week's queries.
- `next_week_data/`: Contains the cumulative historical dataset (baseline LHS + previous weekly queries) provided by the oracle for all 8 functions.
- `WeekX_submission/`: Archive of the exact scripts and outputs submitted in previous weeks.
- `results_weekX/`: The suggested queries generated by the algorithm for that specific week.
- `progress_tracker_week_X/`: Dashboards and visualizations of function metrics, lengths scales, and 3D surface plots for analysis.

## Workflow

1. Update `next_week_data/` with the latest oracle returns.
2. Run `python bbo_optimize.py --week <N>` to generate raw suggestions.
3. Run diagnostic scripts (`length_scale_tracker.py`) to assess model confidence.
4. Manually review and tweak the acquisition strategy (UCB vs EI) or apply manual coordinate overrides for specific functions.
5. Submit the final coordinates to the oracle.
